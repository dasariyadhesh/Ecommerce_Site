# E-commerce Platform: design notes

> **Status:** this repository holds the design write-up only. The source code has not been published yet.

A server-rendered online shop with separate customer and admin areas, designed on Spring Boot, Spring MVC, Hibernate and MySQL.

## Scope

**Customers**
- Register, sign in, browse the catalogue by category
- Cart and checkout (cart logic was still in progress)

**Admins**
- Manage products, categories, stock and product images
- View the customer list and simple sales metrics

## Planned design

| Layer | Choice | Why |
|---|---|---|
| Web | Spring MVC with JSP + Bootstrap views | Server-rendered pages keep the first version to one deployable |
| Security | Spring Security with `USER` and `ADMIN` roles | Admin URLs are protected by role, not by hiding links |
| Domain | Service and DAO layers over Hibernate entities | Business rules stay out of controllers and can be unit tested |
| Data | MySQL / MariaDB, schema generated by Hibernate | Fast start; would move to versioned migrations (Flyway) before production |
| API docs | Swagger / OpenAPI for the REST endpoints | Lets a separate frontend or mobile app use the same services later |
| Build | Maven | |

```
controller/   HTTP + views, no business logic
service/      business rules (pricing, stock checks, order state)
dao/          Hibernate data access
model/        entities
```

## What would come next

1. Publish the source with tests for the service layer.
2. Replace Hibernate auto-DDL with Flyway migrations.
3. Model order state explicitly (`CREATED → PAID → SHIPPED → DELIVERED / CANCELLED`).
4. Split stock reservation from order placement so two buyers cannot take the last item.
5. Add messaging (Kafka) only once there is a second service that needs order events. Until then it adds operational cost and no benefit.
